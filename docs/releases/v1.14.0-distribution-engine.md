# v1.14.0 — Distribution and EV engine

Phase 3 of `docs/ROADMAP-v2.md`. Closes A3 and the model half of A1, replaces
A6's IV rank proxy with a VRP signal. Method notes:
`docs/algorithms/distribution-engine.md`; the one-page argument for the whole
redesign: `docs/algorithms/01-why-pop-is-not-edge.md`.

## New

- **Market-implied density** from the fitted smile (Breeden-Litzenberger),
  with mass/negativity/mean diagnostics. Under it every fairly priced
  structure has EV = 0; the test suite pins that.
- **Scenario densities**: the market density reshaped to a realized-vol
  forecast (VRP mode), tilted by the user's directional view with a
  conviction slider (Directional), or both.
- **Position metrics** on any density: EV after financing and costs, POP,
  P(max profit), CVaR/VaR 5%, EV per CVaR, expected move, Kelly fraction.
- **Realized-vol forecasters**: HAR-RV (default), EWMA, GARCH(1,1); each
  with a historical-error band where applicable.
- **VRP** = ATM IV − forecast, z-scored against the symbol's archived history.
- Engine entries `implied_density`, `evaluate_position`, `vol_forecast`, `vrp`;
  data service `history` and `forecast`; `GET /data/:symbol/forecast`.
- `POST /calculate` returns an `evaluation` block (market metrics, plus
  scenario metrics when `mode`, `sigmaForecast`, `view`, `conviction`, `costs`
  are supplied). Pass the chain's `smiles[exp]` as `smile` for the implied
  density; otherwise the lognormal at `sigma` is used.

## Not yet changed

The Detector's composite score still uses v1's POP weighting; Phase 4 replaces
it with EV/CVaR ranking on these metrics. Nothing in the UI shows the new
numbers yet (Phase 6).
