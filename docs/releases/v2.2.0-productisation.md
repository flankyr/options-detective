# v2.2.0 — Productisation

Phase 7 of `docs/ROADMAP-v2.md`: the parts that need no owner credentials.
The remaining owner actions are listed at the end.

## New

- **Encrypted credentials.** The Massive key is encrypted with Electron
  `safeStorage` (OS keychain) at rest and reaches the backend and the Python
  engine only through process environment; the backend no longer writes it to
  disk when running under Electron. Settings → Data says which storage is in use.
- **Auto-update** via `electron-updater` from GitHub Releases on launch of a
  packaged build.
- **Disclaimer**: a one-time acknowledgement screen, a permanent footer with
  data attribution, and a glossary entry with the full text.
- `docs/METHODOLOGY.md`: one page on how every number is produced, linking
  the detailed algorithm notes.
- `docs/RELEASING.md`: code-signing routes (Azure Trusted Signing or an OV
  certificate), publishing with `GH_TOKEN`, credential handling.

## Owner actions before public release

1. Rename the GitHub repository to `option-obelisk` (the updater's `publish`
   target already points there) and update `frontend/src/lib/feedback.ts`.
2. Choose a signing route and add the credentials as repository secrets.
3. Have the disclaimer wording reviewed before anything is sold.
4. Run the first release with `GH_TOKEN` so `latest.yml` is published.

## Not done

- Encryption of the local account store at rest (I3) stays documented as a
  limitation; it needs a key-management design that fits per-account data.
- Crash reporting and usage metrics (need a service and a privacy notice).
