# v1.12.0 — Data platform

Phase 1 of `docs/ROADMAP-v2.md`. Market data now comes through one Python
service with swappable providers and point-in-time reads, which is what the
backtester (v2.0) needs. Screening behaviour is unchanged on a live chain.

## New

- `backend/math/data/`: `Provider` interface, `DataService.get_chain(symbol, asof)`.
  Live order: **Massive** (free key, 15-min delayed, greeks + OI) → **yfinance**.
  Historical order: **local archive** → **DoltHub** `post-no-preference/options`
  (end-of-day chains with greeks; no volume/OI, so liquidity is flagged
  unknown rather than faked). Every payload names its `provider`, `asof`, and
  the providers that were tried first.
- Risk-free rate per expiry from the US Treasury daily par curve
  (`data/rates.py`), cached daily, with a flagged flat fallback. The hard-coded
  4% is gone from the data path (the engine defaults still accept `riskFreeRate`;
  Phase 2 wires the curve into pricing).
- Dividend yield (trailing 12 months) on live payloads.
- `GET /data/:symbol?asof=YYYY-MM-DD` returns the chain as it stood that day.
- Settings → Data: source list with configured state, Massive API key, rate
  curve status and refresh.
- `od-math datasvc` entry point (`chain`, `status`, `config`, `rates`).

## Changed

- `dataLayer`, `marketPulse`, `etfScreener`, `icsScreener` all spawn Python
  through one helper (`services/pythonRun.js`) instead of four copies (D5).
- Liquidity gates treat `null` volume/OI as unknown (kept, flagged), not zero.
- `docs/api-schema.md` documents schema v2.

## Known limits

- Massive's free tier has no historical greeks/IV and no one-call historical
  chain, so it is a live source only; history is the archive plus DoltHub.
- The Massive key is stored in plain text under the data directory until
  v2.2 moves it to Electron `safeStorage`.
- Incremental per-expiration refresh (D4) is deferred; the 60 s whole-chain
  cache stays.
